# PR ファイルの確認完了と GitHub の表示状態を連携する

## 目的

全変更行（追加行・削除行）の確認状態がローカルに保存されたファイルを、本人の GitHub PR 上で Viewed にする機能を設計する。

GitHub の Viewed 更新 API には、対象コミットを条件に指定する仕組みがありません。送信前後に PR の差分を照合しても、その間に PR が更新される競合を完全には防げません。最初の実装では、Viewed の読み取りと同期候補の表示までを検証します。外部への書き込みは、本人が対象と競合の制約を確認したうえで有効化する後続段階とします。

## 実装方針

機能は既定で OFF とし、本人が対象リポジトリと認証アカウントの組み合わせごとに有効化した場合だけ同期します。OFF の間は自動同期しません。

有効時は、開いている PR の取得内容と現在の差分が一致し、対象ファイルを一意に識別できる場合に限り、ローカル確認済みから GitHub の本人 Viewed へ片方向に反映します。ファイル単位の完了は、全変更行の確認状態がローカルに保存された後で判定します。

GitHub への更新は、PR レビューの送信や承認とは別の操作です。コメント、Approve、レビュー送信、Unview は行いません。

## 実装詳細

既存の PR 進捗計算とファイル完了分類を使い、追加行と削除行の両方が確認済みかを判定します。除外ファイル、行レビュー対象外のファイル、変更行がないファイルは同期対象から除きます。

同期前に、認証アカウント、リポジトリ、PR、比較対象の差分、ファイルパスを確認します。同期後も本人の Viewed 状態と差分を読み直して結果を照合します。確認できない場合や通信が失敗した場合は同期成功と表示せず、ローカルの確認完了状態は維持したまま、同期結果を未確認または失敗として表示します。

| 例 | 同期 |
|---|---|
| 追加行と削除行を全て確認し、ローカル保存済み | 対象になり得る |
| 追加行は確認済みだが、削除行が未確認 | 対象外 |
| PR または差分が更新され、取得内容と一致しない | 対象外 |
| 除外、行レビュー対象外、変更行なし | 対象外 |

## 完了条件

- 既定 OFF であり、本人がリポジトリと認証アカウントごとに有効化できる。
- ローカル保存に成功した全変更行確認済みファイルだけを候補にする。
- 開いている PR、取得した差分、ファイル識別が一致する場合だけ同期処理へ進む。
- API の成功応答と事後照合が確認できた場合に限り、GitHub 同期済みと表示する。
- PR 更新との競合を完全には防げない制約を利用者に示す。これを許容しない場合は、初段階を読み取りと対象表示までに留める。
- レビュー送信、承認、コメント、Unview、マージを行わない。

## テスト内容

実装時は、ローカル保存失敗、未完了の追加・削除行、除外・対象外ファイル、PR 切替、差分更新、認証アカウント切替、API エラー、送信後タイムアウト、事後照合失敗を模擬し、同期条件と表示状態を検証する。特に送信直前・直後に PR 差分が変わるケースを試し、競合を検出しても成功扱いしないことを確認する。
