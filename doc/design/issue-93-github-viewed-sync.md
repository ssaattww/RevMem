# PRファイルの確認状態と GitHub の Viewed 連携

## 目的

全変更行（追加行・削除行）の確認状態がローカルに保存されたファイルについて、GitHub上の本人の Viewed 状態を確認し、同期候補を表示する。

GitHubの更新APIには対象コミットを条件にする仕組みがありません。送信前後に差分を確認しても、確認の間にPRが更新される競合を完全には防げません。そのため**第1段階では、設定状態にかかわらずGitHubへの更新を一切行いません**。Viewedの読み取りと対象表示までとし、更新を行う第2段階へ進むには、競合リスクを含め別途合意が必要です。

## 実装方針

設定は既定でOFFとし、本人がGitHubのviewer ID、ホスト、アカウント、リポジトリごとに管理します。第1段階では設定がONでも更新しません。アカウントが変わった場合は処理を無効化します。本人を識別できない、未認証、または有効化したアカウントと異なる場合は候補にしません。viewer IDに紐付いていない既存のローカル確認状態は表示だけにとどめ、別アカウントの状態に反映する根拠にしません。

候補は、選択中の開いたPRの取得内容と現在の差分が一致し、対象ファイルをGitHub上のファイルとして一意に識別できる場合だけ表示します。ローカルの確認状態とGitHubのViewed状態は別々に表示し、第1段階では「同期済み」と表示しません。

## 実装詳細

対象PRは、PR固有ID、head SHA、merge-base、originalDiffId、完全な差分で識別します。いずれかが変わった場合や一覧の取得中に別の版へ移った場合、候補を無効にします。ファイルは完全な差分とGitHubの変更ファイル一覧から一意に照合し、追加・削除・改名・コピーのパスを推測しません。

ローカル候補は、既存のPR進捗で全変更行の確認が完了し、保存も成功したファイルに限ります。除外、バイナリ、対象外の文字コード、変更行ゼロは候補にしません。GitHubの `PullRequestChangedFile.viewerViewedState` は同じ版の一覧を最後まで取得した結果だけを採用します。認証エラー・GraphQLエラー・部分取得では `取得不可` と表示し、状態を推定しません。

GitHubの状態は次の意味で表示します。

| 状態 | 表示上の意味 |
|---|---|
| `VIEWED` | GitHubで確認済み。候補から外し更新しない |
| `UNVIEWED` | GitHubで未確認。ローカル完了なら候補になり得る |
| `DISMISSED` | 確認後にファイルが更新された。`再確認が必要` と表示し、古い候補は無効 |

第2段階へ進む場合も、PR更新、ローカル確認の解除、本人変更、設定OFFで保留候補を無効化します。送信後のタイムアウトや事後照合不能は `結果不明` とし、自動再送せず、自動Unviewもしません。本人がGitHub上でUnviewにした状態を、古いローカル情報でViewedへ戻さない設計とします。

## 完了条件

- 第1段階では、設定状態にかかわらずGitHubへの更新がゼロである。
- 本人、ホスト、アカウント、リポジトリごとに状態を分離し、アカウント変更時に処理を無効化する。
- viewer IDに紐付かない既存状態は表示だけとし、自動転用しない。
- 開いたPRの固有ID、head SHA、merge-base、originalDiffId、完全な差分が一致し、ファイルを一意に照合できる場合だけ候補を表示する。
- 改名・コピー等のパスを推測せず、ページング未完了や認証エラー時に部分結果から状態を決めない。
- ローカル確認状態とGitHub状態を分けて表示し、第1段階では同期済みと表示しない。
- 第2段階の更新は別途合意を得るまで実装対象にしない。レビュー送信、Approve、コメント、Unview、マージも行わない。

## テスト内容

第1段階のテストでは、設定がONでも更新APIが一度も呼ばれないことを確認します。viewer ID・ホスト・アカウント・リポジトリの分離、アカウント変更、未紐付けの既存状態、PR・差分・ファイル識別の不一致による候補無効化も検証します。

`viewerViewedState` の複数ページ、部分取得、認証エラーと、`VIEWED`・`UNVIEWED`・`DISMISSED` の表示を確認します。PR更新、設定OFF、本人によるUnview、結果不明のケースでは、古い候補による更新や自動再送が起きず、ローカル状態とGitHub状態が別々に表示されることを検証します。

ローカル保存が失敗した場合、追加または削除の確認が一行でも残る場合、除外・行レビュー対象外・変更行ゼロの場合は、候補が表示されないことを確認します。差分更新、設定OFF、ローカル確認の解除で、更新呼び出しがゼロであるだけでなく、古くなった候補が表示から消えることも確認します。
