## 5. Findings

### T304-R1-P1 — high — open

- origin: introduced_by_change
- location:
  - `src/ui/pr-progress/pull-request-progress-tree-data-provider.ts` の `PullRequestProgressTreeFileNode.source`、`PullRequestProgressTreeHost.openDiff`、`select`
  - `src/core/pr-progress/pr-diff-progress.ts` の `PullRequestDiffProgress` / `PullRequestDiffFileProgress`
  - `src/ui/diff-editor/review-diff-editor-controller.ts` の `OpenReviewDiffInput`
- description: Tree node選択時にhostへ渡されるのは`PullRequestDiffFileProgress`だけである。このrecordはfile ID、old/new path、status、countを持つが、PR context ID、base/head immutable revision、filesystem path semantics、identity-bound diff snapshotを持たない。一方、T303のdiff controllerはそれらを必須入力とする。したがって、選択nodeだけから「そのcontextのexact diff」を構築できず、hostが別途保持する可変なcurrent context/snapshotへ依存しなければならない。`replaceProgress`後も旧nodeを`select`でき、nodeにgeneration/context照合がないため、context切替・revision refresh後に旧file recordと新current contextを組み合わせる実装を防げない。
- impact: T304の依存T301→T303接続がidentity-boundにならず、ユーザーが表示中とは異なるPR contextまたはrevisionのdiffを開く可能性がある。設計2.1の確実性優先、context分離、16.3の「そのcontextのdiff editorを開く」を満たさない。
- evidence:
  - nodeの`source`型は`PullRequestDiffFileProgress`であり、host methodも同型1引数だけである
  - T301のprogress resultはsnapshot identityを出力に保持しない
  - T303の`OpenReviewDiffInput`は`contextId`、`fileSystemPathSemantics`、original/modified各revisionとpathを要求する
  - testは同一object referenceがhostへ渡ることだけを確認し、2 context、revision更新、stale nodeを検証しない
- required action: Treeへ投入するsnapshotまたは各file nodeに、exact context/revision/path semanticsへ結び付いたimmutable open targetを保持する。少なくともcontext ID、base/head revision、old/new path、filesystem semantics、snapshot generationまたは同等のresolver tokenを選択時に渡し、現在snapshotに属さないstale/foreign nodeを拒否する。file ID/pathが同じ2 context、head更新、rename/add/delete、refresh後の旧nodeを含む回帰testを追加する。
