## 指摘事項

- 指摘要約: High 1件、Medium 3件、Low 2件
  - **High-1・blocking normal-path / conservative-failure** — `src/core/pr-progress/pr-diff-progress.ts:126-223`は各hunk内のline cursorを検証するよう改善したが、hunk間整合をraw one-based/zero-count anchorの`hunk.oldStart/newStart`と`previousEnd`の差が等しいかだけで判定する。Git unified diffのcount 0側のstartは実lineではなく直前lineのanchorであるため、この計算はvalidなpure addition/deletionを含む複数hunkでsideごとに1ずれる。例として`@@ -1,0 +2 @@`の追加後にold line 4 / new line 5を置換するvalid diffはold gap `3`、new gap `2`となり拒否される。逆にfirst hunkではprior deltaを検証しないため、oldStart `4` / newStart `5`の同数置換だけを渡すと、前段additionが欠落したincomplete diffでも受理される。T203の`parseCoordinate`と`validateHunks`同様、count 0はanchor、count > 0は`start - 1`へ正規化し、最初からcumulative deltaに対する`newStart`整合、order、non-overlapを検証する必要がある
  - **Medium-1・blocking conservative state identity** — `src/core/pr-progress/pr-diff-progress.ts:294-306`は`reviewContext.files[file.fileId]`から取得した`FileReviewState`の`revisionId`だけを検証し、payloadの`state.fileId`がmap keyおよびdiffの`file.fileId`と一致するかを検証しない。`files.a = { fileId: "b", revisionId: head, modifiedReviewed: [...] }`のような破損・誤routing stateでも、file `a`の確認済み範囲として算入される。AC-24の保守的failureとstate repository contractを守るため、state identity mismatchをrejectするtestとvalidationが必要
  - **Medium-2・blocking TDD / evidence accuracy** — `test/unit/pr-diff-progress.test.ts`はR3対応でAPI・fixtureを大きく再構成した際、以前存在したGitHub統計値の過不足、non-PR context、stale file revision、duplicate file identity、binary exclusionの回帰testを削除している。current testはreviewed context行が進捗へ入らないことも直接検証せず、zero-count hunkを含むvalid multiple-hunk caseとfirst-hunk delta欠落もない。一方、implementation reportの「テスト対象」には統計値過不足、Global/branch/workspace、binaryが記載され、実testと証跡が一致しない。R4 findingを含む失敗testを先行追加し、削除された重要回帰を復元する必要がある
  - **Medium-3・public coordinate contract** — `src/core/contracts/review-state.ts:235-249`は`DiffHunk.oldStart/newStart`を単に「One-based starting line」と定義するが、current T301 testとvalidatorはcount 0時に`0`または直前line anchorを使用する。zero-count anchor例外が共有contractに記載されておらず、T301のgap validatorもこの曖昧さからraw座標を誤って比較している。`DiffHunk`でGit anchor semanticsを明文化するか、全sideをzero-based half-openへ正規化した別contractへ変換してからcalculatorへ渡す必要がある
  - **Low-1・non-blocking malformed-input hardening** — `validateHunkLines`は`oldCount=0`、`newCount=0`、`lines=[]`のzero-zero no-op hunkを受理する。実Git diffでは成立せず、既存T203 parserは明示的にrejectする。進捗分子を直接増やさないためnormal path blockerにはしないが、identity-bound「validated snapshot」の契約としてはrejectが望ましい
  - **Low-2・non-blocking held numeric/performance** — R3 Low 2件は未対応。file/aggregate合計のsafe integer再検証がなく、`intervalCoordinates`はreviewed intervalを全行Setへ展開する。通常の1万変更行規模では問題化しにくいためT607/T603/T606と重なるheld riskとするが、変更座標側をinterval検索する実装なら巨大・破損intervalによる長時間占有を避けられる
- R3 finding disposition:
  - R3 High-1「diff identityとfilesの分離」は`PullRequestDiffSnapshot`でcontext/base/head/originalDiffId/filesを一体化し、contextとcanonical originalDiffIdを照合するためclose可能
  - R3 High-2「hunk line座標未検証」はcontext/addition/deletionのcursor、opposite side、header/body、duplicate actual coordinateを検証するよう改善した。ただしzero-count anchorとcumulative deltaのhunk間検証が誤っているためpartial closeに留まる
  - R3 Medium-1「fixture/TDD不足」は正常addition/deletion/replacement、stale snapshot、line coordinate、multiple hunk、zero denominator、user exclusion reasonを追加した。ただし削除された回帰testとzero-count multiple hunk、first-hunk deltaが不足するためpartial close
  - R3 Medium-2「公開DTO documentation」はsnapshot、result、input、calculatorへproperty contract、座標、zero denominator、除外時count、`@param`、`@returns`、`@throws`を追加したためclose可能
  - R3 Medium-3「実装report・PR本文」はR1〜R3 TDD証跡、current contract、failure artifact、scopeを更新したためclose可能。ただしreportのテスト対象とcurrent test実体の不一致はMedium-2として残る
  - R3 Low-1「safe integer合計」とLow-2「interval全展開」は未対応だが、前回どおりnon-blocking held
