## 2. 失敗原因

`test/unit/t505-review-findings.test.ts` の `T505-R007 follow-up handoff uses the required schema v3 top-level packet and preserves the original payload` は、historical handoff内に次の契約を要求している。

- schema v3のrequired top-level fieldが存在すること
- top-level `handoff:` wrapperを使わないこと
- `source_payloads`がlegacy producer packetをlosslessに保持すること
- legacy packetを `payload: |-` としてhandoff内にinline保存すること

失敗時の `handoffs/issue-1-t505-review-followup-20260806210039.yaml` はflat schema v3への変換自体は済んでいたが、`source_payloads.payload`にはlegacy packet本体ではなく次の参照情報だけを格納していた。

- `preserved_repository_file`
- `content_sha`
- `completeness`

このためhandoff単体では元producer payloadをlosslessに運べず、R007のrequired actionと`chat-handoff-manager`のlossless transport目的を満たしていなかった。テスト失敗は正当であり、テスト側の期待を緩めるべきではないと判断した。

## 3. 修正

Commit `5204ea1737665f8b68937525d155560c12b2cc0a` で historical handoffを修正した。

- `source_payloads.payload`をYAML block scalar `|-`へ変更
- `handoffs/source-payloads/issue-1-t505-review-followup-20260806210039.legacy.yaml`の元packet全文をinline埋め込み
- 独立したlegacy fileは監査用copyとして維持
- `extensions.revmem`へ監査file pathとblob SHAを保持
- top-level schema v3 packet、review/implementation境界、next action、transportを維持
