## Findings

### PR69-R001 — High — Global file node が表示 snapshot の owner/revision identity を失い、別 Context・別 revision の内容を開き得る

- Origin: initial review
- Location:
  - `src/ui/global-understanding/vscode-global-understanding-runtime.ts` (`GlobalUnderstandingTreeDataProvider.getTreeItem`, default `openFile`)
  - `src/t505-global-understanding-source.ts` (`resolveCurrentFilePath`)
  - dependency: `src/ui/current-context/current-context-ui-controller.ts`, `src/ui/current-context/current-context-runtime-coordinator.ts`
  - dependency: `src/t405-pull-request-review-runtime.ts` (`readGlobalHeadFiles`)

#### Description

Global file node の command argument は `node.path` だけで、表示 snapshot を生成した repository/context/revision identity を保持していない。クリック時には `T505GlobalUnderstandingSource.resolveCurrentFilePath()` が mutable な `this.currentContext` を再参照し、その時点の `repositoryRoot` と相対 path を結合する。

Current Context 切替では `acceptRecomputed` / `acceptExplicit` が先に `globalSource.setContext()` で source owner を更新し、その後 `refreshDependents()` で Global Understanding の非同期再計算を行う。一方 `GlobalUnderstandingRefreshController.refresh()` は再計算開始時に既存 Tree model を clear せず、結果到着時に置換する。このため、旧 Context の file node が画面に残っている期間に新 Context の owner で path を解決できる。

さらに PR Context の Global evidence は `PullRequestReviewRuntime.readGlobalHeadFiles()` が immutable PR HEAD から読み、working-tree path の存在を gate にしない契約である。それにもかかわらず click open は local `repositoryRoot/path` の working-tree document を開く。PR HEAD が未 checkout、local 内容が別 revision、または PR HEAD にだけ存在する added file の場合、Global の理解率を算出した内容と開く内容が一致しない、あるいは open 自体が失敗する。

#### Impact

Issue #67 の「対応する対象ファイルが開く」を満たさない経路がある。特に multi-root / Context 切替や保存済み PR Context で、ユーザーが表示中の理解率とは異なる repository または revision をレビューしてしまう可能性がある。RevMem の確実性優先と context 分離の前提にも反する。

#### Evidence

- Global file TreeItem command は `arguments: [node.path]` のみ。
- default open は `source.resolveCurrentFilePath(repositoryPath)` を click 時に呼ぶ。
- `resolveCurrentFilePath` は `this.resolveOwner(this.currentContext)` をその場で評価する。
- Current Context controller は新 snapshot を accept した後に dependent Global refresh を await する。
- Global refresh controller は `await source.recalculate()` の前に old presentation を clear しない。
- PR Global source は immutable HEAD-side text を Global evidence として保持し、working tree の存在を gate にしない。

#### Required action

Global file node に、表示 snapshot と同じ owner/context/revision/content-source identity に結び付いた open target を保持させること。Context/revision が切り替わった旧 node は stale として拒否するか、切替時に同期的に clear/disable し、別 owner へ解決しないこと。

PR Context では Global 計算に使った immutable PR HEAD と同じ内容を開ける経路を使用し、local working tree を無条件に代用しないこと。

回帰テストとして少なくとも次を behavioral に固定すること。

1. repository A の Global node を取得後、repository B へ Context を切替えて再計算完了前に旧 node を実行しても B の同名 path を開かない。
2. PR HEAD が local working tree と異なる/未 checkout のとき、Global node が PR HEAD に対応する内容を開く。
3. PR HEAD にのみ存在する added file を Global node から開ける。

### PR69-R002 — High — PR Progress の `line-review-unsupported` file item はクリックしても対象ファイルを開かない

- Origin: initial review
- Location:
  - `src/ui/pr-progress/vscode-pull-request-progress-tree.ts` (`getTreeItem`, command registration)
  - `src/ui/pr-progress/pull-request-progress-tree-data-provider.ts` (`PullRequestProgressTreeDataProvider.select`)
  - `reports/issue-67-progress-file-open-implementation-202608190816.md`

#### Description

VS Code Tree adapter はすべての PR Progress file node に `reviewRange.openPrProgressItem` を設定する。しかし provider の `select()` は `node.reviewability.kind === "unsupported"` の場合、`line-review-unavailable` を返すだけで `host.openDiff()` その他の open 処理を呼ばない。

対象には binary、invalid encoding、unsupported encoding の file node が含まれる。これらは PR Progress Tree に実際に表示される file node である。

実装レポートも「行単位レビュー対象外 node は既存設計どおり text diff を実行しない。この既存仕様は本 Issue の変更対象外」と明記しているが、Issue #67 の受け入れ条件にはこの例外がない。

#### Impact

「PR Progress / Global Progress の双方」「表示されているファイル項目をクリックすると対応する対象ファイルが開く」という Issue #67 の受け入れ条件を PR Progress 側で満たしていない。クリック可能に見える file item が silent no-op になる。

#### Evidence

- Tree adapter は file node の種類に関係なく command を付ける。
- provider `select()` は unsupported node で open host を呼ばず typed result を返す。
- 新規 Issue #67 テストは PR runtime source に command assignment が存在することを regex で確認するだけで、unsupported node をクリックした際の open behavior を検証していない。

#### Required action

`line-review-unsupported` を含む、PR Progress に表示される file node 全体について「クリックすると対応する対象ファイルが開く」経路を実装すること。line review 用 text diff が利用できないことと、ファイルを開くことを分離すること。

少なくとも binary / invalid-encoding / unsupported-encoding node を command 経由で実行し、対象を open する behavioral regression test を追加すること。

### PR69-R003 — Low — Global file open 失敗が「Global理解率を更新できませんでした」と誤表示される

- Origin: initial review
- Location:
  - `src/ui/global-understanding/vscode-global-understanding-runtime.ts` (open command error boundary)
  - `src/t305-extension.ts` (production `reportError` callback)

#### Description

新規 file open command は open failure を既存 `dependencies.reportError` へ渡す。production composition の `reportError` は Global Understanding の refresh 用として `Global理解率を更新できませんでした: ...` を表示する。

そのため file missing、permission、stale target、document open failure 等の click operation 失敗でも、ユーザーには Global 理解率の再計算が失敗したように表示される。

#### Impact

失敗原因と操作が一致しないため、ユーザーと CI/実機調査時の診断を誤らせる。R001 のような stale/missing target が発生した場合も、open 問題ではなく計算問題として見える。

#### Required action

file open 専用の error boundary / reporter を分離し、少なくとも「Global のファイルを開けませんでした」等、実際の operation が分かるメッセージを出すこと。command handler を behavioral に実行し、open failure が open 用メッセージへ到達するテストを追加すること。
