## Findings

### T601-R001 — High — 同数の重複行を並べ替えた場合に曖昧なLCSを一意と誤判定する

- Origin: introduced_by_change
- Location: `src/application/non-git-snapshots/index.ts` の `uniqueLcsMapping`
- Severity: high
- Required: yes

#### Description

`uniqueLcsMapping`は、現在位置の行が一致すると、その一致を無条件に採用して対角要素のcountだけを引き継ぐ。このため、同じ最大長を持つ別のLCSが「一致行をskipする経路」に存在しても、その経路をcountへ含めない。

`hasChangedDuplicateMultiplicity`は重複行の個数が変化した場合だけ保守的にrejectするため、個数が同じまま並び順が変わるケースはこの欠陥を通過する。

例:

```text
old: A / X / A
new: A / A / X
```

最大長2の対応は少なくとも次の2通り存在する。

1. old `A(0), X(1)` -> new `A(0), X(2)`
2. old `A(0), A(2)` -> new `A(0), A(1)`

しかし現在のDPは先頭`A`一致時に対角経路だけを数えるため、mappingを一意と扱い得る。旧`X`または末尾`A`のどちらが確認済みだったかによって、新内容へ継承される確認済み行が変わるにもかかわらず、`status: mapped`を返す。

#### Impact

曖昧な内容対応を確認済みとして表示し、設計原則「曖昧なら未確認」に違反する。レビュー済みでない行をグレー表示する可能性があり、本機能の信頼性を直接損なう。

#### Evidence

- equal branchは`counts[oldIndex + 1][newIndex + 1]`だけを採用する。
- skip-old / skip-newで同じLCS長を作れる場合をequal branchで比較していない。
- 既存testは重複数が変化する`same / anchor / same` -> `same / same / anchor / same`だけで、重複数が不変の並べ替えを検証していない。

#### Required action

1. 上記または同等のmultiplicity不変・複数最長LCSケースをRed testとして追加する。
2. equal位置でも、対角、skip-old、skip-newのうち最大長を作る全経路を一意性countへ含めるか、より保守的な曖昧性判定へ変更する。
3. 曖昧時に`status: ambiguous`かつ空rangeになることを確認する。
4. focused test、unit suite、current HEAD一致CIを再実行する。
