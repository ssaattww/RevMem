## Findings

### T502-REV-001 — high — 通常のmodified Git fileがT203 mappingを通らない

- Origin: introduced by change
- Location: `src/application/global-review-mapping/global-review-mapping.ts`, `mapRepositoryGlobalStateThroughGitDiff`
- Related dependency: `src/core/git-diff/git-file-state-transition.ts`, `applyGitFileStateTransitions`

#### Description

Global Git mappingは、Global stateを`FileReviewState`へ変換した後、T204の`applyGitFileStateTransitions`だけを呼び出している。T203の通常diff interval mapperは呼び出していない。

T204 transitionはrename、copy、add、deleteをfile identityへ適用する責務であり、renameではない通常のmodified sectionは`kind: "other"`として処理を継続せず、確認済みintervalをmappingしない。したがって通常の内容変更では、変更行を未確認化し未変更suffixをshiftする処理が実行されない。

#### Impact

- T502の「Git diffによるGlobal mapping」を満たさない。
- 通常のmodified fileで、変更部分だけを未確認化して未変更部分を維持できない。
- 実装レポート6.2の「content-changing diffでは変更行を無効化」という記載は、rename同時変更には成立するが通常のmodified fileには成立しない。
- focused testが100% renameだけのため、この欠落を検出できない。

#### Required action

- 通常のmodified sectionをT203 mapperへ通した後、T204のfile transitionと一体化したcomplete snapshotを返す。
- 複数hunk、挿入、削除、置換、前後の未変更range shift、空白/EOL設定を含む通常modified Global regression testを先に追加する。
- rename同時変更と通常modifiedの双方で、変更行だけが未確認化されることを固定する。

### T502-REV-002 — high — snapshot revision更新により変更していないGlobal fileまで表示不能になる

- Origin: introduced by change
- Location:
  - `src/application/global-review-mapping/global-review-mapping.ts`, `mapRepositoryGlobalStateThroughDocumentChanges`
  - `src/application/global-review-mapping/global-review-mapping.ts`, `mapRepositoryGlobalStateThroughGitDiff`
  - `src/application/editor-decoration/normal-editor-decoration-model.ts`, `validGlobalFile`

#### Description

両mapping関数はRepository Global Stateの`currentRevisionId`を`newRevisionId`へ更新する一方、file-level `revisionId`は対象fileまたはT204で処理されたfileだけを更新する。

- document change経路では、編集対象1 fileだけがnew revisionになり、他fileはold revisionのまま残る。
- Git経路では、再利用するT204 contractが「unaffected files may retain their prior file-level revision」を明示しており、通常modified fileもfinding 001の理由でold revisionのまま残る。
- decoration側の`validGlobalFile`は、top-level `currentRevisionId`とfile-level `revisionId`の両方がtarget revisionと一致することを要求する。

この組み合わせにより、1 fileのeditやGit transitionでtop-level revisionが進むと、同じrepository内の変更していないGlobal fileがrevision mismatchとして非表示になる。

#### Impact

- repository-wide Global stateのうち、変更と無関係なfileまで確認済み表示を失う。
- editのたびに他fileのGlobal layerが消えるため、「変更部分だけ無効化する」というGlobal設計に反する。
- T504/T505がこのsnapshotをconsumerとして使用しても、file-level revision mismatchを安全に回復できない。
- 単一file fixtureだけでは再現しない。

#### Required action

- complete repository snapshotをnew revisionへ検証・mappingし、変更していないfileも内容が不変である証拠に基づいてfile-level revisionを進める。
- 証拠がないfileだけをfail closedにし、top-level revisionだけを先行させたmixed snapshotを通常consumerへ渡さない。
- 2 file以上のfixtureを追加し、1 file edit、1 file modified diff、rename、delete後も無関係fileのGlobal intervalが維持されることを検証する。

### T502-REV-003 — high — current PR diffがmissingまたはstaleの場合に下位layerがfail-openする

- Origin: introduced by change
- Location: `src/application/editor-decoration/normal-editor-decoration-model.ts`, `currentPullRequestChangedIntervals` / `createNormalEditorDecorationModel`

#### Description

`currentPullRequestDiff`はoptionalであり、次の場合に`currentPullRequestChangedIntervals`は空配列を返す。

- diff未指定
- context ID不一致
- base SHA不一致
- head SHA不一致
- target file不在
- target path不一致

その後のmodelは空配列を「current PRに変更行がない」と同じように扱い、other-contextとGlobal decorationを通常どおり出力する。

PR contextでcurrent contextのreviewed rangeが空、Global rangeがfile全体、diffがmissingという入力では、現在PRの変更行を識別できないにもかかわらずGlobalだけでfile全体をグレー表示できる。

#### Impact

- T502終了条件「現在PR変更行はGlobalだけでグレーにならない」を満たさない。
- stale、欠落、取得失敗という追跡不能状態が表示優先順位2ではなくGlobal確認済みとして表示される。
- 設計2.1の確実性優先に反する。
- 現在のfocused testはmatching diffの成功経路だけを検証している。

#### Required action

- current contextがPRの場合、下位layerを表示する前提としてidentity-boundでcompleteかつvalidatedなcurrent PR diffを必須にする。
- diffがmissing、stale、不一致、不完全な場合は、少なくともGlobalとother-contextによるPR変更行の確認済み推測を行わずfail closedにする。
- missing diff、stale base/head、context mismatch、file/path mismatch、malformed/incomplete snapshotの回帰testを追加する。

### T502-REV-004 — medium — other-contextとGlobalの部分重複を分割せずhoverを誤表示する

- Origin: introduced by change
- Location: `src/application/editor-decoration/normal-editor-decoration-model.ts`, other-context decoration loop
- Consumer: `src/extension.ts`, `createHoverMessage`
- Regression reference: `test/unit/normal-editor-decoration-overlap.test.ts`

#### Description

current contextはGlobalとの重複をactive/inactive intervalへ分割する。一方other-contextでは、1つのvisible intervalとGlobalが1行でも重なると、interval全体へ`globalActive: true`を設定する。

例:

- other-context reviewed: `[0, 4)`
- Global reviewed: `[1, 2)`

現在のmodelは`[0, 4)`を1 decorationとして`globalActive: true`で返す。UI hoverはそのwhole-line decorationへ`Global: active`を表示するため、Globalでない0行目、2行目、3行目もGlobal activeと表示される。

T106ではcurrent contextの同じ部分重複問題を検出し、active/inactive区間へ分割する回帰testが追加されている。T502のother-context追加で同種の欠陥が再導入された。

#### Impact

- reviewed表示そのものはother-contextの証拠で成立するが、hover metadataが範囲全体について不正確になる。
- current contextとother-contextでGlobal activeの意味が不一致になる。
- 実装レポート6.3の「current context/other context/Globalの重複を非重複intervalへ分解」という記載と一致しない。

#### Required action

- other-contextのvisible intervalもGlobal active / inactiveへ分割する。
- 複数other-contextの優先順位とoccupied intervalを保ったまま、部分重複、完全重複、非重複をtestする。
- UI hoverのinterval単位metadataが正確であることを既存T106 regressionと同じ粒度で固定する。
