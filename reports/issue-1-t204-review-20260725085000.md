## 指摘事項

- **高・blocking normal-path** — `applyGitFileStateTransitions`はcloneしたactive stateをrenameごとに即時更新し、その後のrename元を更新済み`currentPath`から再検索する。このため、同一diff内の正常な同時rename `a.ts -> b.ts` と `b.ts -> c.ts`、またはswap `a.ts -> b.ts` と `b.ts -> a.ts` を正しく処理できない。最初のrename後に`b.ts`が複数存在するか本来のsourceが見えなくなり、後続renameを`missing-source-state`にする、stable IDを誤って選ぶ、または重複`currentPath`を残す。各sectionのsource file IDを変更前snapshotから先に確定し、全mappingの一意性とsource/destination衝突を検証してから結果を一括適用する必要がある。`test/unit/git-file-state-transition.test.ts`には独立directory moveしかなく、rename chainとswapの回帰testがない

## 結果

- 結果: **fail・follow-up必須**
- blocking finding: 1件
- PR HEAD SHAに紐づくCI run #609はsuccessだが、現行testは同時renameのpath衝突を検出しない
- T204の終了条件である一意なrenameとdirectory moveのstable ID維持を満たさないため、現状では承認不可

## 必要な修正

1. rename元のfile ID解決を変更前state snapshotに対して行う
2. 全rename mappingを確定してからstateへ一括適用する

4. `a -> b, b -> a`のswap testを追加する
5. 修正後のPR HEAD SHAに紐づくfocused testと全CIを確認する
