## 4. Findings

### T506-REV-001 — high — document editのGlobal mappingがproduction runtimeへ配線されておらず、T506 testが直接mapper呼出しで欠落を隠す

- Origin: normal review
- Location: `test/integration/t506-global-multi-context.integration.test.ts`（`mapRepositoryGlobalStateThroughDocumentChanges`直接呼出し部）、production `src/t305-extension.ts` / `src/adapters/document-review-state/document-review-state-session-provider.ts`
- Severity: **high**
- Status: open

#### Description

T506 integration testの「変更追従」は、persisted Global stateを取得した後に`mapRepositoryGlobalStateThroughDocumentChanges(...)`をtestコードから直接呼び、直後にcalculatorへ渡して`2 / 5 = 0.4`を確認している。このmapped stateはproduction event pathを経由せず、state repositoryへcommitもされない。

一方、現行productionの`src/t305-extension.ts`では`vscode.workspace.onDidChangeTextDocument`が行うのは`GlobalUnderstandingRefreshCoalescer.request()`だけであり、Global stateのrange mapping / atomic persistenceを行わない。`T505GlobalUnderstandingSource.recalculate()`はowner-wide persisted Global stateを再読込してcurrent open document evidenceと比較するため、編集でcontent hashが変わると`calculateGlobalUnderstandingFileProgressCooperatively()`はそのfileを`stale`としてreviewed count 0にする。

さらに通常editor command/session側の`DocumentReviewStateSessionProvider.openOwned()`もcontent hash不一致を検出すると`removeStaleFile()`でcontext/Global file stateを丸ごと除去する。T502のdocument-change mapperを使って「変更・挿入行だけ未確認化し、不変prefix/suffixをshiftして維持する」経路には接続されていない。

#### Impact

Globalで確認済みのfileを通常editorで1行編集すると、T506 testが期待する保守的mappingではなく、そのfileのGlobal確認済み範囲全体がstale/0扱いになる。後続sessionを開けばpersisted Global file state自体も削除されうる。

そのため以下をproduction経路で満たしていない。

- T506の「変更追従とGlobal集計を通す統合」
- Global自動反映の受入条件
- 編集後に未変更Global範囲を確実に維持する設計contract
- 編集後・再起動後にmapping済みGlobal stateから同じ理解率を再現する受入証拠

CIがgreenでも、testがmapperを直接呼ぶためこのwiring欠落を検出できない。

#### Required action

1. productionの`TextDocumentContentChangeEvent`経路からT502 Global document-change mapperを呼び、current context / owner-wide Globalのcomplete snapshotをT501/T104のatomic transaction contractでpersistする。
2. edit invalidation/history contractが要求するeventをT206経路で記録し、stale CAS時は最新snapshotからmappingを再計画する。
3. TDDで、実Extension Host上の通常editorを編集して、変更・挿入行だけGlobal未確認、未変更prefix/suffixはmapping維持となるRed regressionを先に追加する。
4. 同じtestでGlobal Understandingがmapped stateから再集計され、Extension Host restart後も同じ理解率になることまで確認する。pure mapperの直接呼出しだけをacceptance evidenceにしない。
