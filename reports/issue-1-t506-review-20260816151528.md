## 5. Finding

### T506-REV-001 — high — document editのGlobal mappingがproduction runtimeへ配線されておらず、T506 testが直接mapper呼出しで欠落を隠す

- Origin: normal review
- Location: `test/integration/t506-global-multi-context.integration.test.ts`; `src/t305-extension.ts`; `src/adapters/document-review-state/document-review-state-session-provider.ts`
- Severity: **high**
- Status: open

T506 integration testの「変更追従」はpersisted Global stateを取得した後、testコードから`mapRepositoryGlobalStateThroughDocumentChanges(...)`を直接呼び、戻り値をcalculatorへ渡して`2 / 5 = 0.4`を確認する。このmapped stateはVS Code document-change event pathを経由せず、repositoryへcommitされない。

productionの`src/t305-extension.ts`では`vscode.workspace.onDidChangeTextDocument`が行うのはGlobal Understandingのinvalidate/debounced refreshだけである。content change eventのrange/offset/textをT502 mapperへ渡す処理、context/Global complete snapshot更新、atomic persistence、edit history記録はない。

その結果、編集でopen documentのcontent hashが変わるとT505 Global Understanding calculationはpersisted Global fileを`stale`としてreviewed 0扱いにする。通常editor session/decoration pathでもcontent hash不一致はfile全体staleとして扱われ、後続write sessionではfile stateを丸ごと除去しうる。

README自身がこのproduction runtime配線をT506の解消対象としているため、implementation reportの「T506受入にproduction `src/**`変更不要」という結論とも矛盾する。

### Impact

1行だけ編集しても、変更行だけ未確認化して未変更prefix/suffixを維持する設計挙動にならず、file全体のGlobal理解が失われる。T506の変更追従、Global集計、再起動後理解率の受入条件をproduction経路では満たさない。

### Required action

1. `TextDocumentContentChangeEvent`のcomplete change listをproduction mapping pathへ渡し、contextとowner-wide GlobalをT501/T104のatomic contractでpersistする。
2. T206の`invalidated-by-edit` historyを成功transaction後に記録する。
3. stale CAS時は最新complete snapshotと同じdocument-change evidenceから再計画し、片側だけを更新しない。
4. Red Extension Host regressionを先に追加し、通常editorで確認済みfileを実際に編集して、変更・挿入行だけ未確認、未変更範囲shift維持、Global Understanding再集計、restart後同一理解率までproduction pathで確認する。
5. implementation report/handoffの「production変更不要」と受入達成主張を修正後evidenceへ同期する。
