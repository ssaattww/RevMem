- Node runtime factoryからtermination graceを設定できるか

### Architecture CI gate

- `Architecture validation`がsourceのpositive gateを実行する

- positive logとnegative logを別fileへ保存する
- expected violation modeは件数一致時にexit 0、相違時にexit 1となる
- Run #1169と#1173でpositive/negativeの両stepがsuccessとなった

### Blob timeout lifecycle

- timeout時にSIGTERMを送信してからもstdout/stderrを収集する
- `close`eventを待ってからfailureを確定する
- partial output、timeout値、終了signalを`GitCommandFailedError`へ保持する
- grace経過後にSIGKILLへ移行する
- SIGTERMを無視するfixtureがnatural exit前にSIGKILLで終了する
- SIGKILL後もcloseしない場合はstream破棄・unrefによるbounded failureを返す
- runtime optionsから`blobTerminationGraceMs`を設定できる

### Design

- 設計書は`doc/design/vscode-review-range-tracker-design.md` rev4の1file
- process failure contractへSIGTERM、SIGKILL、close event、signal送信失敗、bounded failureを記載した
- test方針へarchitecture両gateとdesign contract test discoveryを記載した
- task identifierとPR経緯を含まない
