## Implementation

### Typed privacy-safe diagnostic

`OperationFeedback` now accepts an explicitly typed structured diagnostic for PR Progress acquisition failure:

- stable code: `PR_PROGRESS_UNAVAILABLE`
- acquisition attempts: the existing closed `PullRequestDiffAcquisitionAttempt[]`
- each attempt is validated against the explicit source allowlist:
  - `local-git`
  - `github-patch`
  - `github-content`
- each reason is validated against the complete `PullRequestDiffUnavailableReason` closed enum.

`OperationDiagnosticError` copies and freezes those validated values. It does not depend on or emit its mutable `Error.message`.

The Output projection renders only the validated structure, for example:

`PR_PROGRESS_UNAVAILABLE attempts=local-git:missing-revision -> github-patch:network; final=github-patch:network`

The final cause is the final attempted `source:reason`. An empty attempt list is rendered using `none`; no repository identity, path, PR title, source text, token, or credential field exists in the structured diagnostic.

### PR Progress wiring

`progressFor()` no longer constructs:

`new Error("PR progress is unavailable: ...")`

for the fail-closed acquisition result. It now reports:

`new OperationDiagnosticError({ code: "PR_PROGRESS_UNAVAILABLE", attempts: result.attempts })`

through the existing `reportActiveOperationFailure("PR進捗を取得", ...)` boundary.

Unexpected thrown errors still use the generic privacy-safe error path, so arbitrary dependency text remains redacted.

## Regression coverage
