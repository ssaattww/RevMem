## Implementation details

### R60-001 — immutable PR snapshot is authoritative

Changed `src/t405-pull-request-review-runtime.ts`:

- `readGlobalHeadFiles()` no longer uses the mutable working-tree `candidatePaths` set as an existence gate for PR snapshot files.
- The validated PR snapshot supplies the PR file universe.
- HEAD-side paths are checked directly with the shared `ReviewFileExclusionPolicy`, then read from the exact immutable HEAD revision.
- Deleted files remain scanned from exact BASE and cached for PR completeness, but are not returned as Global HEAD evidence.
- `candidatePaths` remains in the provider request contract as diagnostic/context information, but does not control immutable PR file existence.

Changed `src/t505-global-understanding-source.ts`:

- `capturePullRequestHeadFiles()` accepts immutable PR HEAD evidence even when the mutable repository path walk does not contain that path.
- Returned immutable PR paths are independently checked with the shared exclusion policy.
- Active-PR available paths are the union of mutable working-tree candidates and accepted immutable PR HEAD paths.
- Global opened evidence and opened/unopened counts are projected against that union, so an unstaged working-tree deletion/rename cannot erase a file that still exists at the accepted PR HEAD.

Regression coverage includes both the T405 content-read boundary and the T505 Global aggregation boundary with a deliberately missing working-tree path.

### R60-002 — rev4 Global semantics explicitly superseded

Updated `Design/BreakingChanges.md` using the repository's existing design-override mechanism.

The new 2026-08-18 policy explicitly supersedes `doc/design/vscode-review-range-tracker-design.md` rev4 §11.3 and §12 where they require repository-wide content classification/all-target-line denominator behavior. It records:

- ordinary Global line progress uses only once-opened/retained evidence for the current owner revision;
- unopened ordinary files are counted by path but are not proactively read or content-classified;
- active PRs are an explicit exception and use the immutable validated PR snapshot;
- modified/added/renamed/copied files are read from exact HEAD;
- deleted files are read from exact BASE for PR completeness;
- dirty working-tree existence is not an immutable PR HEAD inclusion criterion;
- only HEAD-side PR evidence enters the Global denominator;
- exact-revision caches are reused, and superseded owner revisions are evicted.

The regression test verifies both the explicit rev4 supersession and the permanent behavioral clauses.

### R60-003 — one retained revision per stable owner

Changed `src/t505-global-understanding-source.ts`:

- Added `activeEvidenceKeyByOwner`, keyed by the stable serialized review-state target.
- Activating a new revision for the same owner deletes the prior revision from both `openedEvidenceByOwner` and `pullRequestEvidenceByOwner`.
- Evidence access now requires the owner/revision to still be the active key.
- Active-key checks are repeated around asynchronous path enumeration, PR evidence acquisition, persisted Global loading, and calculation boundaries so an older in-flight recalculation cannot recreate an evicted revision after a newer revision becomes active.
- Returning to an older revision therefore requires fresh evidence; previously retained arrays/hashes do not silently revive.

This bounds retained T505 parsed/opened evidence to one revision per stable owner target instead of accumulating every historical revision during a long Extension Host session.
