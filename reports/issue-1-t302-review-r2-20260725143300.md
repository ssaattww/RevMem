## 確認結果

### Git failure分類

- commit確認は`rev-parse --verify --quiet <oid>^{commit}`を使用する
- exit 1だけを`missing-revision`とする
- `ls-tree`の非0 exit、fatal 128、repository破損・権限相当のfixtureは`GitCommandFailedError`を保持する
- 前回blocking findingは解消済み

### immutable identity

- descriptorとURIに`revisionSource: "git-commit"`がある
- revisionはlowercase full SHA-1またはSHA-256だけを受理する
- moving refはURI encode前およびcontent lookup前に拒否される
-同じcanonical URIがref更新によって別contentを返す経路はない

### repository path

- application共通validatorをcodec、Local Git source、adapterで再利用する
- POSIXの特殊filenameをactual temporary Git repositoryでcommit・lookupしている
- Windowsのseparator、drive、control、禁止文字、末尾dot・spaceを拒否する
- `ls-tree -z`のNUL終端と最初のtabだけをmetadata separatorとして扱い、filename内newline・tabを維持する

### blob・encoding

- raw blobは`spawn`によるstreaming readerで取得する
- 4 MiB直下・直上のUTF-8 fixtureが成功する
- invalid UTF-8 fixtureは`invalid-encoding`になる
- replacement characterを生成して成功扱いにする経路はない

### URI・public contract

- base64url canonical性、不正UTF-8、userinfo、password、port、field byte上限、URI length上限をunit testで確認した
- actual `vscode.Uri`でparse・serialize・decode・provider委譲をExtension Host testで確認した
- application、adapter、UI barrelのconsumer fixtureがContract typecheckを通る
