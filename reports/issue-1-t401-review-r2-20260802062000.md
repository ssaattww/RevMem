## 新規Finding

### T401-R003 — High — paginationの`Link`先へ認証tokenを無条件転送する

- Origin: introduced_by_fix
- Location: `src/adapters/github/fetch-github-pull-request-adapter.ts` `nextPageUrl` / `findOpenByHead`
- Description: `Link` headerの`rel="next"`から得た絶対URLをorigin、protocol、API pathを検証せず次のrequest URLとして採用し、初回requestと同じ`Authorization: Bearer <token>` headerを送信する。したがって、responseが`Link: <https://attacker.example/...>; rel="next"`を返すとtokenが別originへ送信される。
- Impact: private repository用GitHub access tokenがGitHub API origin外へ漏えいし得る。token scopeが既定の`repo`であるため、private repositoryへの広いアクセス権を失う可能性がある。
- Evidence:
  - `nextPageUrl`は`new URL(match[1])`の成功だけを条件にURLを返す。
  - pagination loopは返されたURLをそのまま`fetchImplementation(url, { headers })`へ渡す。
  - `headers`にはconstructorで渡されたtoken由来のAuthorization headerが保持され、pageごとのorigin判定はない。
  - 現在のpagination testは同一originのnext URLだけを扱い、cross-origin next linkを拒否するtestがない。
- Required action:
  - `rel="next"` URLは少なくとも初回API URLと同一originであることを検証し、異なるorigin・protocol downgrade・不正なAPI pathをAPI failureとして扱うかpaginationを安全に中止する。
  - cross-origin `Link`を返すfixtureを追加し、外部originへのrequestが一度も発生せず、Authorization headerが転送されないことをTDDで固定する。
  - 同一originの正規paginationが引き続き成功することを回帰確認する。
