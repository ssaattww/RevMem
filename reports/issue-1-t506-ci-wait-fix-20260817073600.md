## 原因

同一HEAD `9eac042...` で、pull_request eventのCI `31975412813` はsuccessだった一方、push eventのCI `31975410323` は `T506 Global multi-context integration` の `t506-workspace-mark-edit` だけ失敗した。

failure artifact `9270925615` のExtension Host diagnosticを確認したところ、外側のlaunch timeoutは `120000ms` でありtimeoutしていなかった。実際の失敗は次のdecoration assertionだった。

- expected: `[0,1), [2,3)`
- actual: `[0,2)`

Global Understandingは編集直後でも行数だけを見ると一時的に `2/3` になり得るため、従来の`waitForMappedUnderstanding()`はmapping/decorationsの反映完了前に待機を終了できた。その直後にdecorationを1回だけrefreshしてassertしていたため、CI負荷によって旧decorationを観測するraceがあった。

## 修正

production code、workflow、他のテストには触れていない。

`test/vscode/t506-workspace-suite/index.ts`だけを次のように変更した。

- mapped state待機上限を `5_000ms` から `15_000ms` へ拡張。
- Global Understandingだけでなく、期待するmapped decoration `[0,1), [2,3)` が観測できるまで50ms間隔でrefresh/pollする。
- 既存の最終assertion自体は維持し、期待する挙動は変更していない。
