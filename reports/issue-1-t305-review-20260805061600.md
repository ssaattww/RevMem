## Findings

### T305-R1-001 — High — context選択が実際の切り替えを行わない

- Origin: introduced_by_change
- Location: `src/t305-extension.ts`; `src/ui/current-context/current-context-ui-controller.ts`
- Description: `selectContext()`は現在の`recompute()`結果だけをQuick Pickへ1件表示し、選択されたdescriptorを返すだけで選択状態を保存・適用しない。controllerも返却値を利用せず、直後に`recompute()`を再実行するため、選択前と同じactive editor由来contextへ戻る。
- Impact: `reviewRange.selectContext`を実行しても別contextへ切り替えられず、設計上の「現在コンテキストの切り替え」を満たさない。Status Barからの選択操作も実質的にno-opとなる。
- Evidence: runtime sourceのQuick Pick候補は`[{ label: snapshot.context.label, ... }]`の1件のみ。`CurrentContextUiController.selectContext()`はselectionの存在だけ確認し、selectionを状態へ反映せず`refresh()`を呼ぶ。既存unit testも返却descriptorが適用されたことを検証せず、次の`recompute()`結果が表示されることだけを期待している。
- Required action: 利用可能なreview context一覧を取得し、選択したcontext identityをauthoritative selection stateへ反映するport/runtimeを実装する。選択後のrecompute・decoration・tree・status barが同一の選択contextを参照するruntime testを追加する。

### T305-R1-002 — High — PRコンテキストの解決と必須表示項目がruntimeに存在しない

- Origin: introduced_by_change
- Location: `src/t305-extension.ts`; `src/ui/current-context/current-context-ui-controller.ts`
- Description: 型と表示projectionには`pull-request`があるが、runtimeの`recompute()`はLocal Git inspectionからbranch/workspaceしか生成しない。GitHub PR resolver、PR title/state、base/head、GitHub接続状態、Global表示状態の供給経路もない。
- Impact: GitHub PR上で作業していてもCurrent Contextはbranch表示のままで、設計のPR優先表示およびCurrent Context Viewの必須情報を満たさない。PR progress等の後続UIが同じcontext identityへ結合できない。
- Evidence: `recompute()`のreturn pathは`workspaceSnapshot()`、workspace descriptor、`branchDescriptor()`だけである。`CurrentContextDescriptor`にもPR state、repository、GitHub connection、Global layer状態を表すfieldがない。PR snapshotはunit test fixture内にのみ存在する。
- Required action: 既存GitHub/PR取得portとLocal Git repository identityを組み合わせてPR contextを解決し、PR未解決時だけbranch/workspaceへfallbackする。設計記載の表示項目をmodelへ追加し、PR resolved/unresolved/GitHub failureのruntime testsを追加する。

### T305-R1-003 — Medium — runtime統合テストが構造文字列検査に留まり欠落を検出できない

- Origin: coverage_miss
- Location: `test/unit/vscode-current-context-runtime.test.ts`; `test/unit/current-context-ui.test.ts`
- Description: VS Code runtime testはsource textに登録API名が含まれることだけを確認しており、command実行、Quick Pick選択、active editor変更、stale refresh、dependent decoration同期の実挙動を検証しない。controller testのselect caseも選択結果を利用しない現実装を正としている。
- Impact: T305-R1-001とT305-R1-002のような主要仕様欠落がfocused test・全CIを通過する。登録解除、二重dispose、例外時同期等のruntime regressionも検出困難である。
- Evidence: `vscode-current-context-runtime.test.ts`は`assert.match`によるsource文字列検査のみ。`current-context-ui.test.ts`は`selectContext()`が返す`selected` descriptorをassertせず、別途queueされたrecompute snapshotを期待する。
- Required action: VS Code API boundaryをfake化したbehavioral testまたはExtension Host testを追加し、command registrationからselection state反映、UI/dependent refreshまで検証する。controller testは選択結果を無視するcontractを撤廃する。

### T305-R1-004 — Medium — `tasks/tasks-status.md`がT305の実装状態と同期されていない

- Origin: introduced_by_change
- Location: `tasks/tasks-status.md`; implementation handoff/report
- Description: task trackingは依然としてT504を現在タスクとして示し、T305/PR #42の状態を記録していない。実装handoffはprogress-management Skill不在を理由にheldとしている。
- Impact: repositoryのauthoritative task stateとPR実態が不一致となり、後続workerが誤った現在タスク・依存状態を参照する。
- Evidence: reviewed HEADの`tasks/tasks-status.md`先頭は現在タスクをPR #39 T504としている。PR #42本文・handoffにも未同期が明記されている。
- Required action: repository規約で許可されたprogress-management Skillを用いて、自タスク範囲だけT305の状態・PR・reportを同期する。Skillが実行環境にない場合は、必要Skillを提供した上で更新を完了し、未同期のままready for reviewとしない。
