## finding fix verification

### T501-R1-P1: addressed

`hasSemanticChange()`はrangeのみの比較から、対象fileの永続化対象snapshot比較へ変更された。

Context fileで比較する項目:

- `schemaVersion`
- `fileId`
- `currentPath`
- `previousPaths`
- `revisionId`
- `modifiedReviewed`
- `originalReviewedByDiff`
- `contentHash`
- `lineCount`

Global fileで比較する項目:

- `fileId`
- `currentPath`
- `revisionId`
- `reviewed`
- `contentHash`

file entryの片側または両側が`undefined`の場合も、存在状態が異なればsemantic changeになる。`updatedAt`だけの差分は比較対象外であり、操作による実質的な永続化内容が変わらない場合は従来どおりno-opとなる。

追加testで次を確認している。

1. review rangeが全行で同一でも、既存Context/Global fileの`currentPath`がtargetと異なる場合はcommit/historyを1回実行し、next snapshotへtarget pathを反映する。
2. Context/Globalに対象file entryがなく、0行fileの`mark-file-reviewed`でrangeが空のままでも、新規entry作成としてcommit/historyを1回実行する。

前回findingの直接原因と、要求した2種類のsibling caseをともに閉じている。

## 追加確認

### correctness / edge cases

- file entry存在差分を`undefined`比較で検出するため、0行fileや空rangeでも初期化が失われない。
- ContextとGlobalのどちらか片側だけentryが欠ける場合もsemantic changeとなり、atomic transactionで整合状態へ更新される。
- `previousPaths`は順序を含めて比較され、rename履歴の差分を破棄しない。
- `originalReviewedByDiff`はkey集合と各rangeを比較し、original側解除をno-op判定で失わない。
- content hashの有無・値、line count、revision、path差分を検出する。
- top-level stateの`updatedAt`だけの差分はhistoryを増やさない。core Review State Serviceが同一target file以外を変更しない現行contractと整合する。

### dependency impact

- transaction生成は既存T102 Review State Serviceを継続利用し、validation、normalization、Context/Global full snapshot生成の責務を重複実装していない。
- commit順序はT104 atomic committer成功後にT206 history requestを行う既存境界を維持する。
- `NormalEditorReviewCommandService`のpublic result、confirmation境界、line count照合に追加変更はなく、今回のfixは内部no-op判定だけへ限定される。
