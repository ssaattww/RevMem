## 7. 指摘事項

### T505-R001: review command直後のGlobal再計算がactive editorの未保存内容ではなくdisk内容を使用する

- Severity: **high**
- Origin: `introduced_by_change`
- Location:
  - `src/extension.ts` のdocument descriptor生成と`reviewStateChanged`発火
  - `src/t305-extension.ts` のreview-state変更subscription
  - `src/t505-global-understanding-source.ts` の`recalculate()`
  - `src/adapters/repository-files/node-global-understanding-file-source.ts`
- Description:
  - normal-editor commandは`editor.document.lineCount`と`editor.document.getText()`のhashを使って、未保存bufferを含む現在のdocument evidenceをContext/Global stateへatomicに保存する。
  - commandが`applied`になるとT505は直ちに`reviewStateChanged`を発火し、Global理解率を再計算する。
  - しかしT505 sourceはopen document evidenceを受け取らず、T503 enumeratorと`NodeGlobalUnderstandingFileSource`でdisk fileだけを再列挙・read/hashする。
  - そのため未保存bufferとdiskが異なる通常操作で、commandが保存したGlobal evidenceと再計算側evidenceが一致しない。
- Impact:
  - 非空行数が同じ編集では、今確認した行が`stale`として0行扱いになり、Global理解率へ反映されない。
  - 非空行数が変わる編集では、T503のdisk分母とT504のload evidence照合が不一致になり、recalculation全体がrejectされてTree/Status Barがclearされる。
  - save eventはT505 refresh triggerへ接続されていないため、保存後もmanual refresh、context変更、設定変更、または別のreview commandまで誤表示・非表示が残り得る。
  - 「review-state変更後にGlobal再計算する」という本PRのproduction経路が、同じ操作で確定したcurrent evidenceを表示できない。
- Evidence:
  - `src/extension.ts`はdescriptorへlive editorの`lineCount`と`stableHash.digest(editor.document.getText())`を設定する。
  - 同fileはcommand resultが`applied`の場合に`reviewStateChanged.fire()`する。
  - `src/t505-global-understanding-source.ts`は`NodeRepositoryFileEnumerator`と`NodeGlobalUnderstandingFileSource`だけを生成し、visible/open documentのcontent・line denominatorを渡していない。
  - Node file sourceは`readFile(absolutePath)`のbytesをhash・scanする。
  - 現行T505 source testはdisk内容とGlobal content hashが一致するfixtureだけを検証する。
- Required action:
  1. 未保存active bufferとdisk内容が異なる状態でreview commandを適用し、直後のGlobal表示が同じlive evidenceを使用するRed testを先に追加する。
  2. T505 recalculationへopen documentのimmutable content snapshot、line count、hashを注入し、同一pathはdisk sourceより優先する。分母も同じsnapshotから作り、enumeration分母との混在を避ける。
  3. save/closeによってevidence sourceが切り替わる場合のrefresh/invalidationを追加し、古いbuffer snapshotを公開しない。
  4. T506の広域edit/multi-context試験とは分離してもよいが、T505が発火するreview command直後の経路は本修正で固定する。

### T505-R002: snapshot file-size設定が全snapshotの合計容量budgetとしても作用する

- Severity: **medium**
- Origin: `introduced_by_change`
- Location:
  - `package.json` の`reviewRange.maxSnapshotFileSizeBytes`
  - `src/application/non-git-snapshots/non-git-snapshot-settings.ts`
  - `src/application/non-git-snapshots/index.ts` の`NonGitSnapshotTracker.save()`と`cleanup()`
- Description:
  - manifestと設計は設定を「Git管理外ファイルの1 snapshotで許可する圧縮後の最大byte数」と定義する。
  - resolverはこの値を既存`NonGitSnapshotLimits.maxCompressedBytes`へ直接設定する。
  - trackerは同じ`maxCompressedBytes`をsnapshot単体のreject条件だけでなく、storage内全snapshotの`totalBytes`整理上限にも使用する。
- Impact:
  - それぞれは設定値未満の正常な複数snapshotでも、合計が設定値を超えるとoldest-firstで削除される。
  - ユーザーが「1 file/snapshot上限」を変更したつもりでも、無関係なfileの最新世代を含む保持容量が同時に縮小し、Gitなしの確認済みevidenceが早期に失われる。
  - `maxSnapshots`とretentionの独立した保持policyが、公開設定の説明にないaggregate byte制限で上書きされる。
- Evidence:
  - manifest descriptionは明示的に`1 snapshot`と記載する。
  - `resolveConfiguredNonGitSnapshotLimits()`は`maxSnapshotFileSizeBytes`を`maxCompressedBytes`へ設定する。
  - `NonGitSnapshotTracker.save()`は`compressed.byteLength > maxCompressedBytes`をrejectする。
  - `cleanup()`は`totalBytes > maxCompressedBytes`の間、古いsnapshotを削除する。
  - T505 testはresolver objectのfield mappingだけを確認し、複数snapshotの保持意味を確認していない。
- Required action:
  1. per-snapshot上限とaggregate storage budgetを別contract・別fieldへ分離する。
  2. `maxSnapshotFileSizeBytes`はsnapshot単体の可否だけへ適用し、aggregate容量は独立した明示設定または既存固定policyを使用する。
  3. 複数の個別有効snapshotの合計がfile-size設定を超えても、その設定だけを理由に既存snapshotが削除されないRed testを追加する。
  4. aggregate limitを公開仕様とする判断なら、設定名・設計・manifest・移行意味を変更し、per-file上限を別に用意する。

### T505-R003: Global理解率が共有effective除外policyを使わず、不正設定時にPR進捗と分岐する

- Severity: **medium**
- Origin: `introduced_by_change`
- Location:
  - `src/t305-extension.ts` の`readExcludeGlobs`
  - `src/t505-global-understanding-source.ts` の`new ReviewFileExclusionPolicy(...)`
  - 直接依存`ReviewFileExclusionPolicyService`と`ReviewFileExclusionConfigurationController`
- Description:
  - base extensionは`ReviewFileExclusionPolicyService`を共有ownerとして使用し、configuration controllerが不正globをcatchして直前の有効policyを維持する。
  - T505 compositionはそのservice snapshot/revisionを利用せず、VS Code設定のraw配列を直接読み、再計算のたびに別の`ReviewFileExclusionPolicy`を構築する。
  - 設定change eventはGlobal refreshを発火するため、negation、brace不整合、展開上限超過等の不正値ではT505側だけがthrowして表示をclearする一方、PR側/shared serviceは直前policyを維持する。
- Impact:
  - 設計の「PR進捗とGlobal理解率で同じ除外policyを再利用する」を満たさない。
  - 同じ設定snapshotに対して、PR Progressは旧有効policy、Global Understandingは非表示という異なる状態になる。
  - 設定訂正までGlobal理解率全体が利用不能となり、除外数・分母の一貫性も保証できない。
- Evidence:
  - `ReviewFileExclusionConfigurationController.applyCurrentConfiguration()`はerror時に`showConfigurationError`だけを呼び、serviceの直前policyを置換しない。
  - base runtimeはserviceのcanonical `getUserGlobs()`を既存consumerへ提供する。
  - `src/t305-extension.ts`はraw `workspace.getConfiguration(...).get("exclude")`をT505 sourceへ渡す。
  - T505 sourceはraw配列から独立policyを毎回生成する。
  - T505 testは有効な既定globだけを使用し、invalid-after-validの共有挙動を検証しない。
- Required action:
  1. base runtimeから共有serviceのcanonical effective snapshotとrevisionをproduction portとして公開するか、T505へ同じpolicy service/application portを注入する。
  2. T505 sourceはraw設定を再compileせず、PR Progressと同じaccepted policy snapshotを使用する。
  3. valid設定適用後にinvalid設定へ変更した場合、PR/Globalの双方が同じ直前policyを維持し、Global表示をclearしないRed testを追加する。
  4. configuration revisionをT504 cache keyへ含め、同一effective policyのno-op変更では不要な再計算を抑止する。

### T505-R004: 不正なsnapshot上限値がExtension activation全体を同期例外で停止する

- Severity: **medium**
- Origin: `introduced_by_change`
- Location:
  - `package.json` の`reviewRange.maxSnapshotFileSizeBytes`
  - `src/application/non-git-snapshots/non-git-snapshot-settings.ts`
  - `src/extension.ts` の`NonGitSnapshotTracker`構築
- Description:
  - resolverは0以下、非整数、safe integer外の値を`RangeError`でrejectする。
  - manifestは`minimum: 1`を持つがmaximumを持たず、runtime取得値に対する型・範囲fallbackもない。
  - activationはresolverを同期的に呼び、その例外を設定errorへ変換せず、tracker構築からextension activation全体へ伝播させる。
- Impact:
  - 1つの設定値が不正または表現可能範囲外になるだけで、Global UIだけでなく確認・解除、装飾、Current Context、PR Progressを含む拡張全体がactivationできない。
  - 利用者は設定UIを開いて原因を直す以外の機能を利用できず、設定境界のfail-closedがproduct全停止へ拡大する。
- Evidence:
  - T505 unit testは0を渡すとresolverがthrowすることを期待する。
  - `src/extension.ts`は`activate()`内で`resolveConfiguredNonGitSnapshotLimits(...)`を直接tracker constructorへ渡し、catch/fallbackを置かない。
  - manifestはsafe integer以内を保証するmaximumを定義していない。
- Required action:
  1. invalid、非整数、safe integer外のeffective settingでactivationが継続し、明示的error通知と安全なdefaultまたはsnapshot機能限定disableになるExtension Host/activation Red testを追加する。
  2. manifestへruntime contractと一致するmaximumを追加し、runtimeでも型・範囲を検証する。
  3. 設定不正をbase feature全体のactivation failureにせず、last-known/default limitを適用するかnon-Git snapshot機能だけをfail closedにする。
  4. 採用したfallbackと再読み込み要否をmanifest descriptionとreportへ記録する。
