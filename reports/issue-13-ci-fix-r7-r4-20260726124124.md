## 指摘事項

- 指摘要約または「指摘なし」: R7でbase providerのstale cleanupが`save`からCAS `commit`へ変わったが、reconciled provider内の`CapturingRepository`はbase providerの初期promotionだけを捕捉する前提のままcleanup transactionも捕捉していた。このためcleanupが永続化されず、baseline refresh testでは古いfile rangeが残った。cleanupの`unmark-file-reviewed` transactionだけは実repositoryへ即時委譲し、成功後にcacheを更新するよう修正した。さらにA cleanupの前にBのCAS更新を挿入する回帰testでは、AのCASがstaleになった後もcapturing cacheが古いsnapshotを返し続けてretryが無限反復したため、`StaleReviewStateError`時にも実repositoryから最新target snapshotを再読込してcacheを更新するよう修正した。これによりB更新はA cleanupより先にcommitされ、Aは最新Globalで再計画する。

## 結果

- 結果: baseline refresh behaviorとR7 stale Global保全を同時に満たした。変更はreconciled providerのcapture adapterに限定し、cleanup CAS/retry、message、interleaving testの期待値を変更していない。`npm run build`、`npm run lint`、`npm run test:unit`（214/214）、focused対象を含むbaseline/R6 test file、`git diff --check`がすべてGreenである。
