## レビュー観点

- workspace membershipよりGit ownershipが優先されること
- workspace外Git fileとuntracked fileがrepository-relative identityを使用すること
- attached branchとdetached HEADが異なるcontext identityへ解決されること
- Gitの明示的な非repository診断だけを非Git fallbackへ分類すること
- UNC authorityがcanonical URIとexternal-file identityから消えないこと
- external-file、workspace、Git repositoryの保存先とcontext kindが混線しないこと
- context/Globalがatomicに更新され、debounce queueとconfirmation commitが同じtargetへ直列化されること
- owner昇格時にcontent hashとline countが一致する確実な範囲だけを移行すること
- decoration readが状態を初期化・昇格・永続化しないこと
- revisionまたはcontent不一致時に保存済み範囲を無条件に再ラベルしないこと
- 既存workspace、Git、PR persistence contractを壊さないこと
- READMEと設計追補が実装後の制約を正しく説明すること

## 検出・修正事項

### 独立再レビュー結果

現行headを対象に、PR差分、主要実装、設計追補、回帰test、既存レビューレポートとその修正内容を再確認した。

追加のblocking findingおよびnon-blocking findingは検出しなかった。

確認した主要事項:

- `DocumentReviewStateSessionProvider`はGit inspectionをworkspace membershipより先に実行し、repository検出時はworkspace内外を問わずGit ownerへ解決する。
- Git file IDはrepository IDとrepository-relative pathから生成され、Windows semanticsではdrive、case、separator差を正規化する。
- external-fileはcanonical URIを保持する専用context descriptor、専用repository target、専用storage rootを使用する。
- persistence公開境界はtarget kindとcontext kindの組み合わせをsave、load、getCurrent、commitで検証する。
- external-file transactionは独立したdebounce keyへmappingされ、pending saveとcommitの順序が保持される。
- owner昇格は移行先に状態がない場合に限り、移行元のcontent hashとline countが一致し、現在documentに対して有効な範囲が存在するときだけ実行する。
- decoration readは不一致範囲を返却値から除外するだけで、状態の作成、削除、昇格、保存を行わない。
- Local Git inspectionは明示的な`not a git repository`診断のみを非repositoryへ分類し、権限、timeout、破損repository等の失敗を伝播する。
- READMEの対応範囲と制限はIssue #13後のowner routing、Git revision mapping未実装、UNC security準拠を反映している。
