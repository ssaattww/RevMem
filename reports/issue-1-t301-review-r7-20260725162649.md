## 指摘事項

- 指摘要約: High 2件、Medium 5件、Low 2件
  - **High-1・blocking incomplete added/deleted snapshot** — `src/core/pr-progress/pr-diff-progress.ts:192-215`は`added`についてold pathなし・deletion 0・各hunkのoldCount 0だけ、`deleted`についてnew pathなし・addition 0・各hunkのnewCount 0だけを検証する。追加fileはbase側が空なので、非空なら完全patchは`oldStart=0, oldCount=0, newStart=1`から全追加行を連続して含む必要があり、削除fileも`oldStart=1`から全削除行を一つの完全なold-side sequenceとして含む必要がある。現行test helper `addition(..., coordinate)`は`coordinate=100`で`oldStart=99,newStart=100`のadded fileを生成し、R6 lineCount test自身が不可能なfixtureになっている。stateがない、またはlineCountとreview intervalを100へ合わせれば、このpartial added patchを正常な1行変更として受理・100%算入できる。T402のpatch欠落・不完全時fallback要件を満たすため、added/deleted statusはempty fileを除き完全file hunkであることを検証する必要がある
  - **High-2・blocking current-content bound** — `src/core/pr-progress/pr-diff-progress.ts:224-225,263-280`はstate `lineCount`に対してaddition座標だけを検証し、modified-side context座標、hunk `newStart/newCount`、zero-count anchorを検証しない。例えばlineCount 1に対し、old 100を削除してnew 100をcontextとするdeletion hunkはaddition集合が空なので通り、original interval `[99,100)`があれば1/1=100%を返せる。same-head stateが存在する場合は、additionだけでなく全modified-side lineとhunk end/anchorがcurrent lineCount内であることを検証し、不完全diffを拒否する必要がある
  - **Medium-1・state routing/path identity** — stateはmap key、payload fileId、revisionだけを照合し、`FileReviewState.currentPath`をdiffのhead-side pathと照合しない。same fileId・same revisionで別pathのstateが誤routingされてもmodifiedReviewedを算入できる。少なくともadded/modified/renamed/copiedではcurrentPathをcanonical newPathと照合し、deletedは明示的な別contractにする必要がある
  - **Medium-2・exclusion-dependent state validation** — nonbinary diff構造は除外前に検証されるよう修正されたが、state identity/revision/lineCount/intervalは`decision.excluded`の後で検証する。同じreview contextの破損stateが除外中は成功し、設定変更でincludeした瞬間にfailureとなる。T300の設定変更再評価を決定的にするため、stateのidentity/revisionと基本boundsは除外設定に関係なく検証し、集計だけをskipする必要がある
  - **Medium-3・blocking cumulative TDD regression** — current test suiteはR6ケースを追加する際に再び大幅に縮小され、implementation reportが「累積テスト対象」とするnon-PR context、stale file revision/payload ID、unknown status、context-only/zero-zero、source統計値、duplicate file ID/path、rename-only zero denominator、user/binary exclusion reasonなどを検証していない。現行79行のsuiteとreport 56〜66行の証跡が一致せず、過去review findingが恒久回帰として保持されていない。各review対応でtestを置換せず累積させる必要がある
  - **Medium-4・synchronous memory/time exhaustion** — `intervalCoordinates`はreview intervalを1行ずつSetへ展開する。`lineCount`はsafe integerであれば上限がなく、original intervalにはupper bound自体がないため、破損persisted stateや非常に大きなfileでExtension Hostを同期的に長時間占有できる。changed coordinate集合をintervalへ照合する方式、正規化intervalのbinary search、または明示上限に変更し、PR progress refreshの計算量をchanged-line数中心にすべきである
  - **Medium-5・stale PR evidence** — implementation reportはR6まで更新されたがPR本文はR3時点のtest-first/Green/validation説明のままで、R4〜R6のcommit、failure artifact、final head/runを記録していない。PR本文とreportのTDD証跡・実装契約を同期する必要がある
  - **Low-1・identity boundary** — empty contextId/baseSha/headSha/fileIdと、baseSha===headShaなのにchanged filesがあるsnapshotを拒否しない。実GitHub SHAはhex commit IDであるため、non-empty formatとno-op revision/files整合を境界で固定する余地がある
  - **Low-2・derived safe-integer arithmetic** — hunk start+count、anchor+count、cumulative delta、file additions+deletions、aggregate totalのderived値がsafe integerかを再検証しない。通常規模では到達しにくいが、pure APIのfailure contractとしてoverflowを推測せず拒否する余地がある
- R6 finding disposition:
  - excluded nonbinary fileの構造validation skipは、binary以外を除外前に`changedCoordinates`へ通すためclose可能
  - modified path equality、renamed/copied path差、added/deleted side count、secondary path normalizationは改善した。ただしadded/deletedの完全file条件がなくHigh-1として残る
  - actual addition座標とstate lineCountの照合は追加された。ただしmodified-side hunk全体をboundしないためHigh-2としてpartial close
  - file/aggregate partial progressとexcluded count test、公開DTO property JSDocは追加されclose可能
  - PR本文の証跡更新は未解消
- 追加確認でfindingなし: unknown runtime line kind/status、context-only hunk、canonical display path重複、nonbinary excluded diff validation、file/aggregate partial ratio、excluded aggregate count、old/new path repository-relative validation、head SHA限定CIには上記以外の問題を確認しなかった

## リスク

- incomplete added/deleted patchを完全な変更として100%表示し、T402 fallbackを迂回する
- current fileのlineCount外にあるcontext/anchorを持つdiffからdeleted-line進捗を算入する
- stable file IDの誤routingまたはpath更新漏れで別pathのreviewed intervalを算入する
- 除外設定変更によって同じstateのvalid/invalidが切り替わる
- 巨大または破損intervalでExtension HostのUI thread相当処理を長時間占有する
- test置換により過去review findingが再発してもCIが検出しない
