# Issue #103 の実装と検証

Global 確認済みレイヤーの切り替えから、共有され得る VS Code の設定ファイルへの保存を除きました。変更後は、表示の選択を拡張機能のワークスペース状態に保存します。利用者が設定値を直接変えた場合は、その値を優先します。

設計レビュー3件を反映した設計（`f17d10dcb8605f5566df73a4ea4c75df4c49ddc6`）に従っています。状態変更を順に処理し、保存に失敗した操作は確定しません。対象は通常エディターの Global 確認済み表示に限ります。設定を書き換えて出た実際の報告時の差分は取得していないため、報告時と同一原因だとは断定しません。

通常レビュー後、保存に失敗しても最後に観測した設定値を保持し、起動時は購読を登録した後に読み直すよう修正しました。既存の Extension Host 起動を増やさず、単一フォルダーで未生成・既存ファイル・再起動後の復元を確認する試験と、複数フォルダーで実際の装飾・設定ファイルのバイト列・関連する Git の差分を確認する試験を追加しました。

先行版の自動CIでは、実動作試験の中で Git を起動したため既存の試験ルールに違反し、実動作へ進む前に停止しました。Git の確認を既存の試験起動側へ戻し、設定のあるルート、ないルート、保存済みワークスペースの実ファイルを試験内で比較します。また、Global だけの範囲と Context にも属する範囲を別々に用意しました。

現修正版は隔離 Linux で試験ビルド、既存の試験ルールを含む関連59件、lintが成功しました。追加した Extension Host 試験の実行結果は、対象版の自動CIで確認します。
