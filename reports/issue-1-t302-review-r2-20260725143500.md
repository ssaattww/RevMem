## 確認結果

### URI identity

- descriptorは`contextId`、`filePath`、`fileSystemPathSemantics`、`side`、`revisionSource`、`revision`を保持する
- canonical URIは各可変fieldをcanonical base64urlで保持する
- decode後の再encode一致を必須とし、別表現を受理しない
- full SHA-1またはSHA-256 commit object ID以外を拒否する
- context、side、revision、path、filesystem semanticsのいずれかが異なるURIは衝突しない
- URI全長65,536文字はsize判定を通過して構造検査へ進み、65,537文字以上はsize errorとして拒否する

### Git failure classification

- commit確認ではexit 1だけを`missing-revision`とする
- exact path確認ではexit 0かつ空出力だけを`missing-file`とする
- exit 128、権限、repository破損、I/O、timeoutは`GitCommandFailedError`として伝播する
- errorはinvocation、exit code、stdout、stderrを保持する

### Path semantics

- codec、Local Git content source、Local Git Adapterが共有canonical path validatorを使用する
- POSIXではbackslash、tab、newline、その他control characterを保持する
- newline 1文字だけのfilenameも実Git fixtureで取得できる
- Windowsではplatform上表現できないpathを拒否する
- absolute、空segment、`.`、`..`、NUL、不正surrogateを全層で拒否する

### Blob content

- metadata lookupとblob本文取得を分離している
- exact pathはNUL終端`git ls-tree`出力を解析し、newlineを含むpathを安全に照合する
- blob本文はraw byte streamから取得し、`execFile.maxBuffer`の4 MiB制約を受けない
- fatal UTF-8 decoderを使用し、invalid UTF-8は`invalid-encoding`になる
- 4 MiB直下・直上の実blob取得testが成功する

### VS Code・公開contract

- actual Extension Hostで`vscode.Uri.parse`、`toString(true)`、codec decodeを通している
- UI provider adapterはcanonical URIをapplication providerへ変更せず渡す
- application、adapter、UIの公開barrelをconsumer fixtureでcompileする
- CIのContract typecheck stepが成功している

- build、contract typecheck、lint、unit、temporary Git、mock GitHub、Extension Hostが成功した
- T202のrepository inspection、remote normalization、merge-base、object existenceのtestが成功した
