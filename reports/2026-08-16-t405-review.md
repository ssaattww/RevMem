## Findings

### R405-1 — Medium — introduced_by_change

- location: `src/t405-review-contexts-runtime.ts` / `redetectPullRequest`, T404 state-service composition
- description: PRのbase/head更新時にT404 revision mappingが実行されず、同一PRコンテキストを継続できない。
- impact: PRへcommit追加後、View上だけ新HEADになり永続Review Stateは旧HEADのまま。layer操作はrevision mapperへ到達して必ず例外となり、再起動後は旧revisionへ戻る。
- evidence: existing PRはbase/head完全一致時のみ`contextStateService.update()`され、相違時はreturnする。さらにT405がfactoryへ渡すevidence loaderは常に`Revision remapping is not a layer-toggle operation`をthrowする。T404 `update()`はrevision change時mapperを必須とする。Design 6.1は同じPR context継続を要求。
- required action: T404の実immutable revision evidence loader/mapperをproduction compositionへ接続し、base/head変更時にcontext/globalをmapping後commitする。revision change→layer toggle→restartをruntime testする。

### R405-2 — Medium — introduced_by_change

- location: `src/t405-review-contexts-runtime.ts` / `redetectPullRequest`, T401 `findOpenByHead`
- description: GitHub上でopen PRがclosed/mergedになっても永続PR stateを更新せず、AC-21のclosed PR管理へ遷移できない。
- impact: 実際にclose/mergeされたPRが保存stateではopenのまま残り、saved-open表示・open既定layer状態が残る。productionからT404のclosed/merged保存能力へ到達できない。
- evidence: T405は`findOpenByHead()`のみを呼び、生成stateも常に`state: "open"`。候補0件時はin-memory currentをclearするだけでT404 stateをclosed/mergedへ更新しない。closed testは最初からclosed fixtureを保存した列挙testのみ。
- required action: 既存PR identityの現在stateを取得し、open→closed/mergedをT404へ永続反映する。saved-closed/merged表示とdefault layer OFFをtestする。

### R405-3 — Medium — introduced_by_change

- location: `src/t405-review-contexts-runtime.ts` / `ReviewContextDiffDocumentProvider`, `openPullRequestDiff`
- description: Review Contextsから開くdiffがT302 canonical review diff経路を迂回する。
- impact: `review-range-pr-context` diffではT303 review commandが`review-range-diff`以外を拒否するためoriginal/modifiedの確認・解除が動かない。context/revision identity contractも失われる。binary fileもlocal `git show`成功時はtextとして開く余地があり、T304の「対象外はtext diffを開かない」契約を迂回する。
- evidence: T405は独自scheme+random token URIを生成し直接`vscode.diff`を呼ぶ。T302 `ReviewDiffEditorController`はcanonical URIへcontext、filesystem semantics、side、revision source、immutable revision、pathを埋め込む。既存command routeは`review-range-diff`のみ受理。
- required action: T302/T303のcanonical diff controller/content providerを再利用し、added/deletedのempty side、binary/encoding対象外を既存contractどおり扱う。Review Contexts起点の両側review操作をExtension Host testする。

### R405-4 — Medium — introduced_by_change

- location: `src/application/review-contexts/review-contexts-controller.ts`, `src/ui/review-contexts/vscode-review-contexts-runtime.ts`, `package.json`
- description: 「コンテキスト表示から削除」がcurrent contextではno-opになり、hidden IDだけが保存される。
- impact: current PR/branch/workspaceで操作しても直後に消えず、同じIDが後にsaved扱いになった場合だけ突然非表示になる。UI操作と結果が一致しない。
- evidence: `hide()`は全itemで提供されhidden IDを保存する一方、`projectReviewContexts()`はhidden filterをsaved側にしか適用せずcurrentは必ず表示する。unit testもcurrent PR hiddenを表示する期待値に固定。
- required action: 現行designどおりcurrentもpresentation-onlyにhide可能にするか、仕様変更ならcurrent itemからcommandを除去しdesign/taskを整合させる。current PR/branch/workspaceをtestする。

### R405-5 — Medium — introduced_by_change

- location: `src/application/review-contexts/review-contexts-controller.ts`, `src/ui/review-contexts/vscode-review-contexts-runtime.ts`
- description: Review Contexts Viewにdesign 16.4で要求された各contextの進捗表示がない。
- impact: current/saved PRを並列管理してもレビュー進捗をViewから判断できず、T304依存を利用していない。
- evidence: `ReviewContextListItem`にprogress fieldがなく、Tree row/tooltipはcurrent、title/state、layer、base/headだけ。T304 progress modelへのproduction接続なし、testsにもprogress assertionなし。
- required action: T304のprogress contractを再利用してcurrent/saved PRの進捗をprojectionし表示・testする。非PR contextはaccepted designに沿う表現を定義する。

### R405-6 — Low — introduced_by_change

- impact: userがtrueへ変更しても挙動は変わらず、公開設定が無効。README設定表にも存在しない。
- evidence: layer defaultは`isPullRequestDecorationEnabled()`の`decorationEnabled ?? state === "open"`だけで決まり、T405 production codeにconfiguration readなし。testもmanifest default=falseだけ検査。
- required action: settingを本当に提供するならdefault決定へ配線しfalse/true双方をtestする。designどおり固定OFFならsetting自体を削除する。

### R405-7 — High — introduced_by_change

- location: `src/t305-extension.ts`, `src/t405-review-contexts-runtime.ts`, `src/application/review-context/selected-review-context.ts`
- description: PR再検出結果がCurrent Contextと通常editor review command/decorationsへ接続されていない。
- impact: Review Contexts上ではPRを「current」と表示できても、Current Context/Status Barと通常の確認・解除はbranch contextのまま。再起動するとT405の`currentPullRequests` in-memory mapも空になり、saved PRはcurrentへ復元されない。利用者向けPR review contextがproductionで成立しない。
- evidence: T305 `enumerateContexts()`はbranch/workspaceしか生成せず、`SelectedReviewContext` unionにもpull-requestがない。`runtimePort.setSelectedContext()`へ渡るのはT305 Current Context runtimeの選択だけ。T405 `redetectPullRequest()`は`source.setCurrentPullRequest()`しか行わずCurrent Context composition/selected review contextを更新しない。Design 16.2はPRをCurrent Contextとして扱い、READMEはT405を「利用者向けの選択・再検出・layer管理」の担当としている。
- required action: PR用SelectedReviewContext/CurrentContext snapshotとauthoritative T404 stateをproduction Current Contextへ接続し、redetect/selection/restartで通常review command・decoration・statusが同一PR identityを使うことをtestする。

### R405-8 — Medium — introduced_by_change

- location: `src/t405-review-contexts-runtime.ts` / `redetectPullRequest`
- description: PR再検出がauthoritative stateのload/update/create成功前にin-memory current PRをpublishする。
- impact: state update/create失敗、既存Global revision不一致、R405-1のrevision mismatch等で永続化されていない「current PR」がViewに残る。後続layer操作はcontext不存在/不一致で失敗し、UIとauthoritative stateが分離する。
- evidence: `source.setCurrentPullRequest(local.repositoryId, state)` が `contextStateService.load/update/create` より前。新規contextで`currentGlobalForNewPullRequest()`がundefinedならerrorなしでreturnし、in-memoryだけ残る。create/update throw時もrollback/restoreなし。
- required action: authoritative update/createが成功した後だけcurrent projectionをpublishし、失敗時は以前のcurrent stateを保持/復元する。Global mismatch・repository write failure・mapper failureを注入したruntime testを追加する。

### R405-9 — Low — introduced_by_change

- location: `README.md`
- description: T405 branchのuser-facing documentationが実装後状態と一致しない。
- impact: merge後もREADMEが「Review Contexts Viewも未接続」と案内し、追加された`reviewRange.closedPullRequestLayerDefault`も設定一覧に現れないため、利用可能機能/制限/設定が誤案内になる。
- evidence: README「現在の制限」はReview Contexts View未接続と記載。設定表はshowGlobal/gutter/overview/excludeのみでT405追加settingなし。T108はREADMEとmanifest/実装一致を継続要件としている。
- required action: T405後の実装状態と残るT406制限を分けてREADMEを更新し、R405-6でsettingを残す場合は設定表へ追加する。
